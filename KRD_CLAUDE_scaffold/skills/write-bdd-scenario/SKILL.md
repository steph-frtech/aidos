# Skill: write-bdd-scenario

## Purpose
Create a BDD mirror before implementation.

## When to use
Use before every feature, hook, MCP tool, skill, projection, migration, context rule or runtime behavior.

## Inputs
- idea or change request
- scope
- truth kind
- authority
- expected observable behavior

## Outputs
- `.feature` file or equivalent mirror
- linked Truth or Idea
- failing red scenario

## Stop conditions
- scenario is executable or marked human-reviewed
- owner/authority is declared
- scope is declared
