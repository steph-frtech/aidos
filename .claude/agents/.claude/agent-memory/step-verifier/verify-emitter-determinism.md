To verify a deterministic emitter/codegen step (S34 Emitters, and the later projection teeth S36 API / S37 DB / S38 Web), the cheap authoritative determinism check is: re-run the materializer and confirm it produces NO git diff.

**Why:** The done-criterion "same source → byte-identical output" is best proven against the actual committed bytes, not just the property test. On S34 `go run ./runtime/generators/cmd/materialize` (from `back/`) re-emitted `back/gen/` + `front/web/gen/`; `git status --porcelain back/gen front/web/gen` showed only the untracked-dir markers, no content change — so the committed artifacts are byte-stable. The protected header `CODE GENERATED BY AIDOS — DO NOT EDIT. source: <hash>` is on line 1 of every emitted file; `Drifted(ledgerHash, onDisk)` + fixture D cover hand-edit detection.

**How to apply:** Run the step's materialize command, then `git status --porcelain <gen dirs>`. A content diff = a determinism gap (clock/RNG/map-order leak) = residual issue. The front TS twin (`lib/<name>.ts`) must sort fields BEFORE hashing and mirror gofmt's space-padding exactly to stay byte-identical to the Go `go/format.Source` output — check both renderers sort fields first if source_hash must be field-order-independent.

**Cross-language byte-identity (the load-bearing twin claim):** these steps assert the TS twin matches Go by pinning Go output hashes in a TS data file (e.g. S37 `front/web/lib/db-projection-data.ts` exports `GO_CREATE_OUTPUT_HASH` etc.). To verify the pin is HONEST (not stale), drop a throwaway `_test.go` in the gen package that re-hashes `EmitX(...).Bytes` with sha256 and prints it, run it, then grep the printed hashes against the TS data file — they must match exactly. The TS vitest passing alone only proves TS-vs-pin, not TS-vs-Go; the throwaway cross-hash proves the pin tracks the live Go emitter. S37: CREATE 0d87b161…, EXPAND 32910b8f…, NARROW 05815fae… all matched.

**S38 (web projection, ts-next × control):** done criterion = a playwright-bdd e2e (`tests/e2e/web-preview.spec`, 6/6) proving the EMITTED `_generated/checkout-button.tsx` respects its control-spec fixture. Authoritative determinism check that worked: drop a throwaway `_test.go` re-emitting via the real anchors `control.CheckoutButton()` + `action.CheckoutSubmit()` and sha256 the bytes — got source `8ebfb46f…`, output `5b428d00…`; then `sha256sum` the on-disk file — must equal the output hash (it did). Cross-check the panel's `MATERIALIZED_OUTPUT_HASH` const equals that too. SCAR: `page.tsx` header comment cited a stale wrong output hash (`96b5d172…`) while the panel const was correct (`5b428d00…`) — harmless but doc-drift; fix the comment. Note `control.Control.VisibleWhen/EnabledWhen` are `expr.Expr` (use the anchors), but the *canonical wire* form is `json.RawMessage` — emit via `Emit`, never hand-build the canonical struct. i18n keys for `/web-preview` (namespace `webPreview`) all present — but always run the node cross-check anyway (see [[feedback-i18n-keys-missing]]).

**S37-specific (DB projection):** the done criterion is a Testcontainers dry-run on real Postgres (`migration_dryrun_test.go`, ~10s, skipped under -short — run WITHOUT -short to actually exercise it). Confirm: a seeded historical row survives the EXPAND with the new column NULL (no data loss), the agent role can SELECT but not INSERT `runtime.data_truth_scope` nor `kernel.entity` (wall), and the strategy CHECK refuses a value outside the closed set. Note: the SQL CHECK `body->'migration'->>'strategy' IN (...)` passes (NULL) if the migration block is absent — harmless since the Go guard enforces a well-formed body, but flag if a later step relies on the CHECK alone.
