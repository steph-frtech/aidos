# ADR 0078 — Governance branchée sur les VRAIS AgentRun (ledger Merkle vivant, OWASP/policy sur un chemin de décision)

- **Statut :** accepté (décision humaine, 2026-06-15 : « GO » sur docs/plan/PLAN-branchements.md)
- **Date :** 2026-06-15
- **Contexte KRD :** CLAUDE.md §1 (loi de complétude — pas de monstre ; un dispositif de preuve qui ne prouve qu'une démo EST un monstre) · §2/§8 (le mur, BA13 `GateAction` — « done » calculé, jamais déclaré) · §6/§8 (determinism-first — le Merkle root est un hash, jamais un « LLM audit agent ») · §9 (anti-overwrite — ledger append-only) · ADR 0009 (un op = un tool MCP) · ADR 0054→0070 (la couche-agent gatée) · ADR 0072 (décision-mère : le Go est l'oracle de vérité, le front l'appelle) · steps BA13 (`GateAction`), GV03 (ledger Merkle), GV05 (`policy.yaml → GateAction`), BA29 (agentrun/agentloop ledger)

## Contexte

L'audit `w91305w3q` (2026-06-15) a relevé que le dispositif de **governance** — ce qui doit *prouver* que la couche-agent respecte le mur, OWASP et les policies — ne prouve aujourd'hui qu'une **démonstration**, pas la réalité. Trois preuves d'audit :

1. **Le ledger Merkle ne voit pas les vrais runs.** `back/runtime/agentrun/ledger.go` (l. 124 `Append`, l. 154 `Root`, l. 194 `Verify`, l. 218 `BuildLedger`) implémente un **ledger tamper-evident** propre et déterministe (un Merkle fold pur des bodies de run, sans clock ni rng — §6/§8). Mais le serveur qui l'expose, `back/mcp/agentloop/ledger.go`, dérive ses runs de **`ledgerRuns()`** (l. 73-133) : une fixture de **scénarios DÉCLARÉS** hardcodés, jamais les `AgentRun` réellement exécutés. Le ledger est tamper-evident sur de la fiction. C'est un monstre §1 : un dispositif de preuve sans chemin vivant — il prouve une démo.

2. **OWASP/policy est un package orphelin.** `back/runtime/governance/` (owasp.go, policy.go, compliance.go, sre.go, adoption.go) porte les couvertures OWASP Agentic Top-10 (`owasp.go`, set CLOSED) et le compilateur **`policy.yaml → GateAction`** (GV05, `policy.go` : le YAML est la *source* déclarée, l'enforcer Go la *projection*, jamais l'inverse — tighten-never-widen, equivalence prouvée par property test). Mais `grep -rln "runtime/governance" back/ --include="*.go" | grep -v _test` rend **zéro importeur hors test** : le package n'est sur **aucun chemin de décision vivant**. La preuve OWASP/policy existe, mais ne garde rien.

3. **Le `GateAction` (BA13) tourne, mais le ledger et la policy ne le rejoignent pas.** `GateAction` est bien le verdict composé consulté **avant** chaque action (`back/runtime/agentloop/drive.go` l. 13-24 : « BA13, the single composed verdict … consulted BEFORE execution »), et le compilateur GV05 le prend déjà pour cible. Le chaînon manquant est l'**alimentation** : ni le ledger ne reçoit le run réel ni la policy.yaml ne se branche au point de décision.

Le concept (§1, §8) est sans ambiguïté : un dispositif de preuve qui ne prouve qu'une démo est un monstre — la honnêteté anti-Goodhart exige que la governance s'exerce sur la **réalité**, pas sur une fixture. ADR 0072 ayant posé le Go comme oracle de vérité, le branchement va dans le sens du concept : c'est le moteur Go qui produit les runs, qui les chaîne, qui les garde.

## Décision

**La governance se branche sur les VRAIS AgentRun : le ledger Merkle reçoit `Append(r)` sur chaque run réellement exécuté (plus les trois fixtures `ledgerRuns()`) ; OWASP/policy entre dans un chemin de décision vivant (le gate BA13 ou un MCP governance) ; et `policy.yaml` se compile en `GateAction` (GV05) sur ce chemin.**

1. **Ledger sur les vrais runs.** Chaque `AgentRun` réellement exécuté par la couche-agent (le loop de `drive.go`/`postcheck.go`) est passé à `agentrun.Append(ledger, r)` — le même Merkle fold pur que GV03, **augmenté** par l'alimentation réelle, jamais forké (anti-duplication §3/§6). Le `ledgerRuns()` à trois fixtures hardcodées (`back/mcp/agentloop/ledger.go` l. 73-133) cesse d'être la source : la fixture peut rester comme **gold de test** (un miroir de reproductibilité), mais le ledger live chaîne les runs vrais. Append-only (§9) : le ledger n'efface ni ne récrit, il chaîne. Le ledger reste **vérifiable** (`Verify` recompute la chaîne — intacte ou rompue, jamais un jugement).

2. **OWASP/policy sur un chemin vivant.** Le package `runtime/governance` (aujourd'hui sans importeur hors test) est **importé** dans le chemin de décision : soit au sein du gate BA13 (`GateAction` consulte les couvertures OWASP avant l'action), soit derrière un **MCP governance** dédié (ADR 0009 : un op = un tool — il n'existe pas encore de `back/mcp/governance`, à scaffolder). Le set OWASP reste CLOSED et déterministe (un LLM scorant la couverture serait un determinism gap, §6 — `owasp.go` l'épingle déjà). La preuve OWASP redevient une garde, plus une étagère.

3. **`policy.yaml → GateAction` (GV05) branché.** Le compilateur de `policy.go` (la YAML déclarée → l'enforcer `GateAction`, equivalence + tighten-never-widen) est mis **sur le chemin** : une policy.yaml chargée projette sa surface sur l'`AgentImplementation` et `GateUnderPolicy` appelle **le même** `GateAction` (verdict single-sourced, ne peut pas dériver — `policy_property_test.go` le scelle). La policy déclarée gouverne réellement les actions, plus un test isolé.

Le determinism-first est **central** ici (§6/§8) : le Merkle root est une fonction de hash pure (jamais un « LLM audit agent »), la couverture OWASP un set clos, le verdict de policy un fold déterministe. La governance branchée *ne sait rien faire de plus* que recomputer — elle ne juge rien qu'elle ne pourrait recalculer. Le mur reste **inchangé** : `GateAction` est consulté **avant** l'exécution (un write au-dessus de la waterline est refusé `AGENT_WRITE_ABOVE_WATERLINE`) ; brancher le ledger et la policy *renforce* la garde, n'ouvre aucune porte.

Branche (du plan) : `back/mcp/agentloop/ledger.go` (l. 73-133 `ledgerRuns()` → alimentation réelle via `agentrun.Append`), `back/runtime/governance/*` (l'importer au point de décision — gate BA13 ou un `back/mcp/governance` scaffoldé, ADR 0009), `policy.go` (GV05) sur le chemin vivant.

## Conséquences

- **Positif.** Le monstre §1 est tué : la governance prouve désormais la **réalité** (les vrais runs chaînés), plus une démo (les trois fixtures). La honnêteté anti-Goodhart (§8) est restaurée — « done » et « conforme » sont calculés sur l'exécution vraie. OWASP/policy quitte le statut de package orphelin pour devenir une garde vivante (plus un importeur réel hors test). GV05 (`policy.yaml → GateAction`) gouverne réellement, single-sourced, sans dérive possible. Determinism-first respecté (Merkle = hash, OWASP = set clos, verdict = fold pur). Anti-overwrite respecté (ledger append-only). Le tout va dans le sens d'ADR 0072 (le Go est l'oracle qui produit, chaîne et garde).
- **Coûts assumés.** (a) Le ledger live grossit avec les runs réels — c'est le coût d'un audit honnête ; il reste content-addressed et vérifiable. (b) La fixture `ledgerRuns()` n'est pas supprimée mais **requalifiée** en gold de reproductibilité (un miroir : mêmes runs → même root) — anti-overwrite, on déprécie via lifecycle, on n'efface pas (§9). (c) Si la voie retenue est un `back/mcp/governance`, c'est un serveur MCP à scaffolder (ADR 0009 — activé + fault-injecté au step qui en a besoin, jamais un hook mort).
- **OpenQuestions (forward-deps, ne bloquent pas).** Le point d'insertion exact d'OWASP dans le chemin de décision (au sein de `GateAction` vs un MCP governance séparé) à figer au step de branchement ; la persistance Postgres du ledger (aujourd'hui en mémoire/transcript — back-fill suivant ADR 0072/0073). Questions ouvertes documentées, jamais des `residual_issues` bloquants (§6, exception bootstrap).
- Le mur, le déterminisme et l'anti-overwrite restent **inchangés** ; cet ADR *augmente* la governance (elle garde le réel, plus la fiction) sans modifier la frontière de vérité ni le verdict `GateAction` lui-même.
