# ADR 0075 — Les hooks du harness tirent vraiment : PreToolUse=mur, Stop=goal-check/completeness/mutation, SessionStart=self-test, PostToolUse=sensors — câblés dans `.claude/settings.json` + fault-injection

- **Statut :** accepté (décision humaine, 2026-06-15 : « GO » sur docs/plan/PLAN-branchements.md)
- **Date :** 2026-06-15
- **Contexte KRD :** CLAUDE.md §1 (Mandat A/B — les deux mandats) · §2 (le mur — défense en profondeur, niveau 1 = hook PreToolUse) · §5 (créer un Hook iff règle non-bypassable ; *hook honesty* : un hook qui ne tire jamais est mort, chaque hook a sa fault-injection) · §6 (la boucle par étape : sensors verts à chaque diff, completeness, Stop bloque) · §8 (stop condition anti-Goodhart : « done » = red→green ∧ green antérieur intact ∧ mutation ≥ seuil ∧ pas de monstre — calculé, jamais déclaré) · §3 (Hooks = binaires Go, *every backend op = MCP tool*) · steps S04 (le mur), S39 (self-test méta-méta), S40 (MutationRunner) · ADR 0072 (le moteur Go est la référence) · audit `w91305w3q`

## Contexte

Le contrat KRD repose sur **deux mandats non-négociables** (CLAUDE.md §1) et un **mur** à défense en profondeur (§2). Le niveau 1 du mur est un **hook `PreToolUse`** (binaire Go) qui refuse toute écriture des zones de vérité ; le **stop condition** anti-Goodhart (§8) est un hook `Stop` qui calcule « done » (goal-check + completeness + mutation). Or l'agent qui **construit AIDOS** lui-même tourne sous un harness dont les hooks doivent tirer pour que ces garanties existent.

Preuves de l'audit `w91305w3q`. Les binaires Go existent et sont verts : `back/hooks/{pretooluse, stop, sessionstart, posttooluse}` (et au-delà : `goal-check`, `memory-firewall`, `promotion-gate`, `sandbox-confinement`, `commit-gate`, `ci-ratchet`, `postkernelchange`…). Mais `.claude/settings.json` ne câble **que** `PostToolUse = e2e-changed-spec.sh` et `Stop = audit.sh` (un scan agentshield). Le mur niveau 1 (PreToolUse), le done-criterion (Stop=goal-check/completeness/mutation), le self-test méta-méta (SessionStart) et le sensor-runner par diff (PostToolUse) **ne sont reliés à rien** : les binaires existent, le harness ne les invoque pas. C'est un **hook mort** au sens de §5 (« un hook qui ne tire jamais est mort ») — pire, c'est le mur du build-agent qui ne tire pas, donc une garantie de §1/§2/§8 qui est, en pratique, débranchée. Cet ADR est orthogonal au choix de runtime (ADR 0072–0074) : il protège l'agent qui *écrit* AIDOS, c'est le plus structurant du contrat KRD.

## Décision

**Câbler dans `.claude/settings.json` les quatre hooks du harness, chacun via un shim `stdin → binaire Go`, avec une fault-injection bout-en-bout (casser ce que le hook surveille → il bloque vraiment) :**

1. **`PreToolUse` = le mur §2 niveau 1.** Le binaire `back/hooks/pretooluse` refuse toute écriture des zones de vérité (`kernel` / `mirrors` / `fitness`) et retourne un `BlockReason` actionnable (`code, severity, explanation, how_to_fix[]`). Câblé sur les outils d'écriture (Edit/Write/Bash de write). C'est le niveau 1 de la défense en profondeur (le niveau 2, les GRANTs Postgres, est inchangé). **Fault-injection** : tenter une écriture kernel/mirrors/fitness → le hook bloque, BlockReason non vide ; couper le hook → l'écriture passerait (preuve que le hook est ce qui garde).

2. **`Stop` = le done-criterion §8 (anti-Goodhart).** Le binaire `back/hooks/stop` calcule « done » : **red set → green ∧ green antérieur intact ∧ mutation ≥ seuil ∧ pas de monstre** (goal-check + completeness + mutation S40). « Done » est **calculé, jamais déclaré** par l'agent (§8). Le scan `audit.sh` (agentshield) existant est **conservé** (CLAUDE.md §10) — il est *ajouté* à, jamais remplacé (meta-loop : on ADD une garde, on n'en RETIRE jamais — §5). **Fault-injection** : laisser un miroir rouge / un mutant survivant / un monstre → Stop bloque la clôture ; tout vert → Stop laisse passer.

3. **`SessionStart` = le self-test méta-méta (S39).** Le binaire `back/hooks/sessionstart` lance la routine de self-test à l'ouverture de session : la fault-injection déterministe qui prouve les trois garanties NIVEAU 3 inviolables — chaque sensor tire encore, le mur tient encore, la fitness est inchangée (aucune boucle n'a édité sa propre fitness, §8). **Fault-injection** : altérer un sensor / le mur / la fitness → le self-test rougit au démarrage.

4. **`PostToolUse` = le sensor-runner par diff.** Le binaire `back/hooks/posttooluse` exécute les sensors sur le diff après chaque écriture (auto-certification sur le computationnel, §6 étape 4). Le `e2e-changed-spec.sh` existant est **conservé** (ajouté à, jamais remplacé). **Fault-injection** : casser ce qu'un sensor surveille → le sensor rougit au diff suivant.

5. **Chaque hook = un shim `stdin → binaire Go`.** Le binaire Go est l'autorité (determinism-first : le jugement du hook est du code déterministe, jamais un LLM, §8) ; le shim shell ne fait que passer le payload `stdin` au binaire et propager son code de sortie / sa décision. Conformément à *hook honesty* (§5), **chaque hook embarque sa fault-injection** : un hook n'est activé que prouvé capable de rougir au moins une fois sur un cas réel.

## Conséquences

- **Positif.** Les deux mandats (§1), le mur (§2) et le done-criterion anti-Goodhart (§8) **tirent réellement** sur l'agent qui construit AIDOS — fini le mur niveau 1 débranché, fini le « done » auto-déclaré. Les binaires Go déjà verts (`back/hooks/*`) trouvent enfin leur chemin d'invocation. *Hook honesty* (§5) honoré : chacun a sa fault-injection bout-en-bout. ADR 0072 cohérent : le binaire Go est l'autorité du jugement, le shim ne fait que l'appeler. Orthogonal au runtime (0072–0074) : protège la phase de build indépendamment.
- **Coûts assumés.** (a) Latence par diff : `PostToolUse` lance les sensors à chaque écriture — il faut qu'ils soient rapides (sinon échantillonner / paralléliser). (b) `Stop` peut bloquer une clôture que l'agent croyait finie — c'est l'effet recherché (anti-Goodhart), mais le `BlockReason` doit rester actionnable (cf. `aidos explain`). (c) On *ajoute* `pretooluse`/`sessionstart` et on *complète* `Stop`/`PostToolUse` sans retirer `audit.sh` ni `e2e-changed-spec.sh` (meta-loop : ADD only, §5).
- **OpenQuestions (forward-deps, ne bloquent pas).** Le seuil exact de mutation (S40) lu par le Stop, et le périmètre des sensors lancés par diff vs en lot (perf), seront calés au branchement. La forme précise du shim (un script par hook vs un dispatcher unique) suit l'implémentation.
- Le mur, le determinism-first et l'anti-overwrite sont **inchangés** ; cet ADR ne fait que *brancher* les gardes que le contrat exige déjà — un hook qui ne tirait pas devient un hook qui tire, et le prouve par sa fault-injection.
