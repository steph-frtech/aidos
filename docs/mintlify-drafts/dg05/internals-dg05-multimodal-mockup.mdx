## Implémentation

**Le seam `MockupAdapter` (`back/runtime/requirementbench/multimodal_dg05.go`)** — l'injectable « modalité » derrière le **même** port que DG02/DG04, l'**analogue modality-agnostic** du `ModelAdapter` :

```go
type MockupAdapter interface {
    ProposeViewSpecs(mockup Mockup) ([]LLMOutput, error) // total, jamais panique
    Available() bool                                     // produit-il sans fallback ?
    Name() string                                        // identité opaque — le rapport en est invariant
}
```

Là où DG04 mappe `Spec → []LLMOutput`, DG05 mappe `Mockup → []LLMOutput` : **même sortie, même juge**. Le `Mockup` est une **représentation EN DONNÉE**, jamais une image binaire :

```go
type Mockup struct { ID string ; Zones []MockupZone }
type MockupZone struct { Kind MockupZoneKind ; Fields []MockupFieldKind ; Actions []MockupActionKind }
```

Les trois enums sont **clos et déclarés** (au-dessus de la ligne, §8) : `MockupZoneKind` (`header`/`list`/`detail`/`footer`/`form`), `MockupFieldKind` (`display`/`input`), `MockupActionKind` (`primary`/`secondary`). **`zoneKinds(zone, vision)`** est le mapping pur d'une zone vers les `RequirementKind` de la **taxonomie close** : la lecture littérale (`vision=false`) ne surface que les facettes directement dessinées ; la **lentille vision** (`vision=true`) infère en plus les facettes transverses qu'une lecture littérale rate — l'**`empty_state`** d'une `list`, l'**`on_success`** d'un bouton `primary`, l'**`on_error`** d'un `secondary`/cancel. Le mapping n'invente **jamais** un type que la maquette ne déclare pas (le mur : le modèle propose **dans** la structure dessinée par l'humain).

**`BenchMockup(adapter, mockup) → (CompletenessMetric, Provenance)`** est le cœur *determinism-first* de DG05, calqué sur `BenchVia` : il construit `SpecFromMockup(mockup)`, appelle l'adapter, **PUIS re-juge TOUJOURS** sa sortie par la fonction pure DG03 (`Metric`, qui réutilise `Derive`/`Extract`). La modalité **propose** du texte, le juge déterministe **compte** les types — le juge **domine**. Dégradation gouvernée : adapter indisponible **OU** `ProposeViewSpecs` en erreur **OU** zéro candidate ⇒ fallback `MockupRecompileReading` (la lecture littérale), **jamais** une erreur d'écran. `usedRealLLM` est reporté via le **même** `realLLMReporter` privé que DG04 (dispatch `mockupUsedRealLLM`) — un adapter qui n'opte pas est déterministe (false par défaut).

**`FixtureMockupModel`** — l'adapter déterministe **sans réseau**, le modèle du **miroir hermétique**. `ProposeViewSpecs` dérive **purement** deux candidates de la maquette : `single` (`mockupTaggedText(mockup, false)`, la lecture littérale) + `vision` (`mockupTaggedText(mockup, true)`, la lentille). `mockupTaggedText` n'émet une ligne taguée que pour les types **surfacés**, dans l'ordre canonique de la taxonomie (le **premier marqueur** déclaré de chaque kind, la même grammaire close que `Extract` parse) → texte **byte-stable**.

**Les attendus mockup-fidèles.** `MockupExpected(mockup)` projette les attendus (le dénominateur de `MatchPct`) depuis la maquette elle-même : l'**union de la lecture-vision** sur toutes les zones — donc il **inclut** les facettes transverses que la maquette *implique* (l'état vide, les effets de succès/erreur), si bien qu'une lecture littérale qui les rate est honnêtement comptée **incomplète**. `SpecFromMockup` emballe ces attendus dans une `Spec` qui nourrit le port/métrique **inchangés**.

**`ProposeViewSpecIdeas(metric) → []firewall.IdeaCandidate`** — la porte du mur. Pour **chaque** `MissingType` (ordre déterministe, zéro LLM), il `firewall.Capture` un candidat puis le route par la **seule** porte légale `firewall.ViaIdea` → idée draft (`WroteKernel=false`). `ToKernel` n'est **jamais** appelé. Le volet multimodal **propose**, il ne déclare jamais la vérité.

## Méta

Le miroir n'est pas un test ajouté : c'est le **done-criterion**, **rouge d'abord** et **hermétique** (tout tourne sur `FixtureMockupModel`, la maquette en donnée, zéro réseau). Cinq propriétés ∀ (`multimodal_dg05_property_test.go`, rapid) cartographient exactement les critères de done DG05 :

1. **`TestMockupCompletenessIsDG03Metric`** — `BenchMockup == Metric` (DG03 pur) sur les candidates produites ; **chaque** type présent est re-surfacé par `Extract` (le juge n'est jamais court-circuité) ; `MatchPct ∈ [0,1]`.
2. **`TestMockupJudgeDominatesModalityIdentity`** — deux adapters **différents** (`FixtureMockupModel` et un `staticMockupModel`) émettant les **mêmes** sorties donnent le **même** rapport (`reflect.DeepEqual`). Le juge domine la modalité.
3. **`TestMockupHolesNeverWriteTruth`** — `ProposeViewSpecIdeas` rend une idée par trou, **chacune** `WroteKernel=false` et de statut draft ; la lecture-vision couvre ses propres attendus (**0 trou** proposé), la lecture littérale laisse exactement les facettes transverses qu'elle rate.
4. **`TestMockupAbsentGovernedFallback`** — un `brokenMockupModel` (Available=false, erreur) ⇒ `FellBack=true`, `UsedRealLLM=false`, le rapport **égale** la métrique de lecture littérale, `MatchPct ∈ [0,1]`. Jamais une erreur d'écran.
5. **`TestMockupAIOffReplayStaysGreen`** — `FixtureMockupModel` rejoué **100×** : rapport byte-pour-byte identique, sans réseau.

Le fixture `multimodal_dg05_fixture_test.go` ajoute le **surplus différentiel** prouvé hermétiquement (la lentille vision récupère l'`empty_state` de la liste que la lecture littérale rate, mesuré par DG03), la porte du mur explicite (`TestMockupNoToKernelDoor` : `firewall.ToKernel` refuse **toujours** l'arête directe Mémoire → Kernel pour la même forme de mémoire que DG05 route), et la **résilience texte-seul** (`TestMockupAbsentTextOnlyStillUsable` : multimodal absent ⇒ lecture littérale gouvernée, **et** le `BenchVia` texte de DG04 reste utilisable — les deux volets indépendants). `usedRealLLM=false` partout : le vrai modèle vision est une **dépendance infra documentée**, jamais le proof.

## Méta-méta

DG05 généralise **§8 — « le juge est déterministe »** d'une modalité (texte, DG04) à une autre (image-mockup) **sans changer le juge**. Tout le monde brancherait un modèle vision *en juge* (« demande au modèle si la maquette est complète ») ; AIDOS l'en **sort** et le confine à **proposer** des view-specs derrière un seam `MockupAdapter`, **toujours** re-jugé par la **même** fonction pure DG03. C'est *determinism-first* (§6) tenu à la lettre : le modèle vision est l'**exception gatée**, isolée à la plus petite surface (`VisionModel.ProposeViewSpecs`, à venir), et la garantie repose sur le chemin **pur** (le `FixtureMockupModel`, la maquette en donnée) — l'IA éteinte, le rejeu reste vert. C'est la même logique de **frontière** que `markitdown` (ADR 0039 : doc→markdown, une porte vers une idée draft, jamais une écriture kernel) transposée à image→view-specs. C'est le **mur** (§2) : `BenchMockup` rend une **valeur** ; les view-specs et leurs trous rejoignent le kernel **uniquement** par `firewall.ViaIdea → idée → miroir → /goal`, jamais `ToKernel`. C'est **modality-agnostic** par construction (§9, additif) : le vrai modèle vision — poids/GPU non garantis ici — se branchera comme **un `MockupAdapter` de plus** derrière ce même port, re-jugé par cette même métrique ; et **multimodal absent**, le sujet reste pleinement utilisable sur le différentiel **texte seul** (DG04) — la dépendance infra est **documentée**, jamais bloquante. L'oracle déterministe de la complétude (ADR 0072) reste **autoritaire** : le volet multimodal **propose** des view-specs, il ne **gouverne** jamais la fermeture d'un goal.
