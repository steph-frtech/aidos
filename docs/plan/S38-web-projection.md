# S38 — Web projection (a Next component emitted from a control/action spec, respecting its control-spec fixture)

Subsystem: AIDOS Workbench | Home: `front/web/app` | Workbench route: `/web-preview`

## Objectif

Land the **web projection emitter**: a deterministic generator that reads a **control-spec** (button, with its `view`, `label`, `visible_when`, `enabled_when`, `triggers` — the Kernel source of S11) plus the **action-spec** it binds (S11), and **emits a real Next.js component** whose rendered behaviour is **byte-for-byte governed by the control-spec fixture** (the `given → {visible, enabled}` state fixture and the `event → invoke` action fixture of S11). This is the front face of "one source → N projections, never double-typed" (S34 emitters extended to the `ts-next` target): the button you click in a browser is a *projection* of the truth, never hand-authored UI behaviour — proven green by a **playwright-bdd** e2e that replays the fixture against the rendered DOM.

## Sortie attendue

Per CLAUDE.md §5 this step needs **pure logic/schema** (a Go emitter package), the **emitted projection** (a Next component under `front/web`), a **repeatable gesture** (the `/web-project` Skill), a **behaviour proof** (the BDD mirror — a fixture + a playwright-bdd e2e), and a **visualization** (a Next route) — and nothing more. It deliberately adds **no** new truth tables and **no** new MCP/hook (justified below).

- **Go package** `back/runtime/generators/webcomponent/` (a new `target` inside the S34 emitter set, **not** a fork of it) — the `ts-next` emitter for `kind: control`. It **reads** a control-spec + its bound action-spec from the `kernel` schema (SELECT-only — the wall, §2; the control AST is the prior truth of S11, never authored here) and emits a typed `Artifact` exactly as S34 defines it: `path` (under `front/web/app/web-preview/_generated/…` — an emitted projection lands in `front/web`, per CONTEXT-MAP "TS types / front projections emit into front/web"), `bytes` (the rendered `.tsx`), `source_hash` (`Hash(Canonicalize(control.body ⊕ action.body))` — **reuse S02's** `Canonicalize`/`Hash`, do **not** fork them), and a stamped **protected header** (`// CODE GENERATED BY AIDOS — DO NOT EDIT. source: <hash>`). The emitted component renders a button whose `visible`/`enabled` are computed from `EvalState(control, given)` (S11's pure evaluator — re-expressed as the component's own pure render logic, **not** a network call: the projection embeds the control's `visible_when`/`enabled_when` Expr semantics so the rendered DOM is a faithful mirror of the fixture) and whose click dispatches the action-spec's `invoke` (resolved by `Plan(action, event)`, S11) — surfaced as a testable signal (a `data-aidos-invoke` attribute / a typed callback), **not** an executed backend call (the operation runtime is a later tooth; here the projection only declares the bind). **Determinism is the contract** (S34): same source ⇒ byte-identical `.tsx` (no clock, no RNG, stable key/attribute/import ordering, normalized newlines). Pure function of `Canonicalize(source)`; no I/O beyond the SELECT and the projected write below the wall.

- **Emitted projection** `front/web/app/web-preview/_generated/<control-id>.tsx` — the **output**, not hand-edited (CLAUDE.md §4/§9): a Next.js (App Router) client component for the control-spec, carrying the protected header + its `source_hash`. It is regenerable and **protected**; staleness (`source_hash` ≠ the control's current head) is **computed** and feeds S22's red wave, never hunted. Registered in the S34 emit ledger (`runtime.generated_artifacts`, reused as-is) with `target = 'ts-next'`, `kind = 'control'` — **no new table**.

- **Skill** `.claude/skills/web-project/` (`SKILL.md`, CLAUDE.md §5: repeatable gesture → Skill) — `/web-project`: the replayable gesture "emit the Next component for a control-spec and verify it respects its control-spec fixture". It encodes the procedure (resolve control + bound action refs from `kernel` → emit the `.tsx` projection with the protected header → record the ledger row via the writer role → materialize the S11 fixture as a playwright-bdd `.feature` → run the e2e → never hand-edit `_generated/`), the **determinism contract** (re-emitting reproduces byte-identical output; a non-deterministic web emitter is a defect, not an artifact), and the **honesty rules** (never invent a `view`, a `label`, a `triggers` ref, a `targetId`, or a business rule the AST does not pin — an unpinned field becomes an **OpenQuestion** in `provenance`, never a guessed default).

- **BDD mirror** — two artifacts by nature, conceptually stored in the `mirrors` schema (`reflects`, `test_kind`, `cert_language`, `liveness`, `authority`) and materialized to `tests/` for the runner:
  - a **fixture** mirror (`state → command → events`, interpreted in Go) over the `webcomponent` emitter: a control-spec AST → `Emit(control, "ts-next")` → an `Artifact` carrying the protected header, the `source_hash`, and a `.tsx` whose render reflects the control's `visible_when`/`enabled_when`. **Testcontainers (Go)** with real Postgres applies the S34 migration so the emit-ledger round-trip is verified, not mocked.
  - a **playwright-bdd** journey/acceptance mirror (front N0 slot — `Playwright + playwright-bdd`, frozen, mandatory): the S11 **control-spec state fixture** (`given → {visible, enabled}`) and **action event fixture** (`event → invoke`) replayed as Gherkin `.feature` scenarios against the **rendered** emitted component on `/web-preview`. This e2e green **is** the done criterion.

- **Next route** `front/web/app/web-preview/` → `/web-preview` — the Workbench panel that renders the emitted component for a chosen control-spec next to its control-spec fixture (the expected `visible`/`enabled` per `given`, the expected `invoke` per click) and a **respects-fixture / drift** badge (does the live DOM match the fixture? is `source_hash` stale vs the control's head?). See "Visualisation UI".

> Explicitly **out of scope** (would be monsters / out of slot here): **no new truth tables / no entity or control AST authoring** — the control-spec + action-spec are prior truth (S11, read-only); this step **reads** them and adds only the `ts-next` projection + a ledger row. **No MCP server** — `Emit` is a pure library and `/web-project` is a harness gesture; no distinct callable backend op emerges here (if a `web_project_emit` op truly emerges, record an OpenQuestion). **No hook** — `_generated/`-protection is already covered: the wall hook (S04) refuses agent writes above the line, and hand-editing a generated `.tsx` is caught by re-emit byte-equality + the PostToolUse sensors; this step adds **no** new non-bypassable rule (§5 hook-honesty forbids a hook that never fired). **No operation execution** — the projected button *declares* its bind (S11's `Plan`); actually running the operation on click is a later tooth. **No new emitter framework** — extend the S34 emitter set with one `target`, never re-implement determinism/hashing/ledger/`Project`. **No targets beyond `ts-next`** and **no controls beyond the button** — the kind × target matrix grows additively.

Watch them go **red** first (no `webcomponent` emitter, no `_generated/` projection, no `/web-preview` route, no playwright-bdd feature). That red **is** the `/goal` for this step.

## Visualisation UI

- **Route:** `front/web/app/web-preview/page.tsx` → `/web-preview` (a **new** route; do not touch `front/web/app/page.tsx`, `layout.tsx`, `globals.css`, or any prior `/control`, `/emitters`, etc. route). The panel: pick a control-spec → render its **emitted** component (imported from `_generated/`) alongside (1) the control-spec fixture table (per `given`: expected `visible` / `enabled`; per click: expected `invoke`), (2) the live DOM state, (3) a **respects-fixture** badge (live DOM == fixture?) and a **stale** badge (`source_hash` == the control's current kernel head?). Read-only; it renders truth's projection, it never authors truth.
- **Playwright e2e:** `tests/e2e/web-preview.spec.ts` (one spec per critical flow, per CLAUDE.md §4 + the `playwright-e2e` skill), driven by the **playwright-bdd** `.feature` materialized from the S11 fixture. It loads `/web-preview` via the configured `webServer` (`npm run dev -w @aidos/web`, baseURL `http://localhost:3000`), and for each fixture row asserts the rendered button's `visible`/`enabled` and the dispatched `invoke` match the control/action spec. Green e2e = done.

## Regle anti-ecrasement

This step edits **only its own declared files** and otherwise **adds new files**: the new emitter package `back/runtime/generators/webcomponent/`, the emitted projection under `front/web/app/web-preview/_generated/` (regenerable, protected, never hand-edited), the new `/web-preview` route and its `tests/e2e/web-preview.spec.ts`, the new `/web-project` Skill, and the new BDD mirror records. It **consumes, never re-implements**: S02 (`Canonicalize`/`Hash`), S11 (the control-spec/action-spec AST + `EvalState`/`Plan` + their fixtures), S34 (the emitter set, the `Artifact`/`Project` shape, the `runtime.generated_artifacts` ledger), S13 (`BlockReason`), S22 (the red-wave staleness consumer), S06 (mirror schema/liveness). It registers `target = 'ts-next'` by **inserting** ledger rows (append-only) — it does **not** alter the S34 table or its GRANTs. Any change to a **prior contract** (the `Artifact` shape, the entity/control AST, the ledger schema, an existing mirror) is forbidden in passing: it goes through a **ChangeSet** (S20) + a **SemanticDiff** (S21) + an ADR, never a silent edit. No prior route, generated file, mirror, or truth is overwritten, replaced, or deleted (CLAUDE.md §9).
