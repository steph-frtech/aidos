# S36 — API projection (Go REST/JSON from operation + entity) + Pact contract

Subsystem: AIDOS Runtime | Home: `back/gen/api` | Workbench route: `/api-projection`

## Objectif

Land the **API projection**: a deterministic emitter that reads an **operation** AST (the N2 workflow, S10) **and** the entity it touches (the N3 source, S35) from the `kernel` schema and emits a **Go REST/JSON handler** into `back/gen/api/` — the projection that exposes a kernel operation over HTTP, never hand-authored, byte-identical per source. The handler's request/response shape is then frozen as a **Pact contract** (the frozen-stack N3 "Pact between cells" slot), verified by a Go **`pact-verifier` MCP** server. The canonical projection is **`createOrder`**, and the done criterion is: **the `createOrder` route passes its contract test.**

## Sortie attendue

Per CLAUDE.md §5 this step needs **pure logic** (the API emitter, a Go package whose *output* lands in `back/gen/api`), **a capability** (the `pact-verifier` MCP — running a Pact verification *is* a callable runner over a service, §5 "run a runner / query a service"), **persistence** (an Atlas migration extending the emit ledger with the `api` target + a Pact-contract record), **a behaviour proof** (the BDD mirror), and **a visualization** (a Next route) — and nothing more (no Skill, no new Hook — see out-of-scope):

- **Go package (the emitter) + emitted output `back/gen/api/`** — the **`api` target** added to S34's `kind × target` emitter set (the emitter logic lives with the generators / N3 codegen slot; its *output* is `back/gen/api`, which is the **home** of this step and is **PRODUCED, never hand-authored**, CLAUDE.md §4/§9). The emitter is a **pure, total, deterministic** function `EmitAPI(operation, entity) → Artifact` — no I/O, no clock, no RNG — that renders a Go `net/http` (or the frozen-slot router; see §c tool-search) handler for **one operation**: it maps the operation's **input** to a typed JSON request body (reusing the entity's `EmitGo`/`EmitTS` field shapes from S35 — never re-typing the entity), maps the operation's emitted **events / result** to a typed JSON response, sets the **method + route** from the operation (`createOrder` → `POST /orders`), and **delegates the body to the operation interpreter** (the N2 Operation DSL in Go, S10) — the handler is a thin, generated transport adapter, it **never** re-implements the business rule. The emitted handler carries S34's protected header (`// CODE GENERATED BY AIDOS — DO NOT EDIT. source: <hash>`) and its `source_hash` is `Hash(Canonicalize(operation ⊕ entity))` (reuse S02's `Canonicalize`/`Hash`, do **not** fork). An operation whose input/output references an entity/attribute/event the AST does **not** pin is **Blocked** with an S13 `BlockReason` (`UNKNOWN_OPERATION_IO`), never guessed — no invented field, no invented route, no invented status code. The emitter only **reads** `kernel` (SELECT-only) and **writes** the projection into `back/gen/api/` — below the wall (§2).

- **`pact-verifier` MCP server** `back/mcp/pact-verifier/` (Go MCP SDK, one tool = one backend op — named in CLAUDE.md §4 `back/mcp/<server>/` list) — exposes a single capability: **verify the emitted `createOrder` handler against its Pact contract** (Pact provider verification, the frozen N5 "Pact provider verification" slot). It is the *runner* the mirror calls: given the contract (the consumer-side expectation: `POST /orders` with the Order request shape → a `200/201` with the Order response shape) it stands the generated provider handler up and asserts the request/response shapes match the contract — the **contract test** the done criterion names. It is a read/run capability (a callable backend op over a service), hence an MCP per §5, **not** a pure library call. The MCP role has **SELECT-only** on `kernel`/the ledger (the wall) and writes nothing to truth.

- **Atlas migration** (`back/migrations/`) — one declarative, **expand-only / append-only** migration that (1) extends S34's emit-ledger `target` CHECK to admit `'api'` (expand-contract: add the value, never drop the prior ones), so an `api` artifact's `source_hash`/`output_hash` are tracked and staleness stays **computed**, and (2) adds a **Pact-contract record** table `runtime.api_contract`: `route text NOT NULL`, `method text NOT NULL`, `operation_hash text NOT NULL` (the operation AST content address the contract was pinned from), `pact_json jsonb NOT NULL` (the contract body), `last_verified_at timestamptz NULL`, `PRIMARY KEY (method, route, operation_hash)`. GRANTs: the agent DB role gets **SELECT only** on `kernel.*` and on `runtime.api_contract` / the ledger (it reads operations + contracts, authors neither — the wall, §2); only the `aidos` CLI writer role inserts/updates a contract row via an approved ChangeSet. Append-only / expand-only; no prior table, value, or GRANT is altered or dropped.

- **BDD mirror** — by the nature of the API projection its required mirrors are: a **fixture** (`state → command → events`: an `operation + entity` → `EmitAPI` → a Go handler artifact carrying its source hash + protected header) **plus** a **Pact contract** mirror for `createOrder` (the consumer expectation, verified by the `pact-verifier` MCP) **plus** a **`rapid` property** mirror for the ∀ determinism / faithfulness invariants. **Testcontainers (Go)** with real Postgres applies the migration so the ledger + contract round-trip and the running provider are verified end-to-end, not mocked. These **are** the done criteria (below), conceptually stored in the `mirrors` schema and materialized to `tests/` for the runner.

- **Next route** `front/web/app/api-projection/` → `/api-projection` — the Workbench panel rendering, for the **`createOrder`** operation: its **emitted Go handler** (read-only, with the protected header and `source_hash`), its **method + route** (`POST /orders`), the request/response JSON shapes, the **Pact contract** body, and a **pass / fail** badge from the last `pact-verifier` run (the contract-test status — the done criterion, visible in the UI). See "Visualisation UI".

> Explicitly **out of scope** (would be monsters / out of slot here): **no Skill** — emitting a projection and running a verifier is the harness's inner codegen/CI, reusing S34's `/project` gesture; this step adds the `api` *target*, not a new replayable human gesture. **No new Hook** — `back/gen/api` protection is already covered by the wall hook (S04) plus re-emit byte-equality + PostToolUse sensors; §5 hook-honesty forbids a hook that never fired. **No operation/entity/DSL AST authoring** — the operation (S10) and entity (S35) are prior truths; here the emitter **reads** them and adds only the projection + contract; defining new operations is not this step. **No API gateway / auth / middleware / pagination / versioning / error-envelope taxonomy** beyond what the operation AST pins — those are later teeth, and inventing them is forbidden (OpenQuestion if a real need appears). **No other operations** — `createOrder` only; the route matrix grows additively, do not pre-build `getOrder`/`cancelOrder`/etc. **No consumer (front) Pact generation** — this step pins and **verifies the provider** side of the `createOrder` contract; the front consumer test is a later front step. **No live server deployment** — the emitter renders the handler; standing it up is done only inside the verifier/testcontainer for the contract test, not deployed.

## Regle anti-ecrasement

This step **edits only its own declared files** — the API emitter logic + its emitted output in `back/gen/api/**` (PRODUCED, never hand-authored), the new `pact-verifier` MCP in `back/mcp/pact-verifier/**`, the new `back/migrations/<new>.sql` (extending the ledger `target` CHECK + adding `runtime.api_contract`), the `mirrors`-stored fixture + Pact contract + `rapid` property materialized to `tests/`, `tests/e2e/api-projection.spec.ts`, and `front/web/app/api-projection/**` — and otherwise **adds new files**. It defines one new contract (the `api` emitter target + `EmitAPI`, the `createOrder` Pact contract, the `runtime.api_contract` table, the `pact-verifier` MCP op); it changes none. Per CLAUDE.md §9: no rewrite of a prior artifact, no **hand-edit of generated files** (`back/gen/api/**` is emitted from the operation+entity source — to change a handler, change the source and re-emit, never edit the output), no silent model replacement, no touching prior Workbench routes; any prior `Stop`/wall hook is **composed/extended additively** (a new artifact may ADD a guardrail, never REMOVE one — §5 meta-loop rule). The migration is **expand-only / append-only**: it *adds* the `'api'` value to S34's ledger CHECK and *adds* `runtime.api_contract`, never altering or dropping a prior table, value, or GRANT. Any change to a **prior contract** it depends on — S02's record substrate / `Canonicalize` / `Hash`, S04's wall GRANT set, S10's operation AST / interpreter, S13's `BlockReason` shape, S34's emit ledger / `Emitter`/`Artifact` shape / protected header, S35's `Entity` AST / `EmitGo`/`EmitTS` / the `Order` example — goes through a **ChangeSet** (`DRAFT → APPLIED`, completeness-gated) plus a **SemanticDiff** on the affected schema/mirror, never an in-place edit. An override is a recorded decision (ChangeSet + ADR + provenance), not an edit.
