# S37 — DB projection (Atlas migration emitted from the entity, expand-contract) + DataTruthScope

Subsystem: AIDOS Runtime | Home: `back/gen/db` | Workbench route: `/db-projection`

## Objectif

Land the **db projection** of an entity (KRD line 532: `db = migrations (expand-contract)`, a **PROJECTION** of `entity`, ai / below the line) — the **Atlas migration emitted** from the entity AST, in an **expand-contract / forward-only** shape — together with **DataTruthScope** (KRD §44.3): the declaration of what a new truth does to **historical data**, so that a change with historical impact **requires a declared migration** (`migration.required: true`, `strategy ∈ {expand_contract, backfill, dual_read, dual_write}`, `audit.preserve_old_truth: true`). The done criterion: the emitted migration **dry-runs valid**, and a **historical-impact change requires a declared migration** (no silent schema change over existing/historical records).

## Sortie attendue

Per CLAUDE.md §5 this step needs **pure logic/schema** (a Go package), **persistence** (the emitted Atlas migration + a `DataTruthScope` record table), a **behaviour proof** (the BDD mirror), and a **visualization** (a Next route) — and nothing more (no new MCP, no new Hook, no Skill — see out-of-scope):

- **Go package** `back/gen/db/` — the **db-projection emitter** and the **DataTruthScope** value object. Two parts, both pure:
  - `EmitMigration(entity, prior?) → Atlas migration text` — a **pure, total, deterministic** emitter that takes the entity AST (the **db PROJECTION** of `entity`, read from `kernel`, never authored here) and, given the prior head shape, renders the **expand-contract / forward-only** Atlas migration that brings the schema to the new head. Reuses **S35's `EmitDDL`** for the target `CREATE TABLE` shape and **S34's** emitter/ledger discipline (one source → projection, byte-identical re-emit, the `source_hash` content address — reuse S02's `Canonicalize`/`Hash`, do **not** fork them). Expand-contract means: a column add is an **additive expand step** (never an in-place `ALTER` that rewrites/drops historical data); a destructive/narrowing change (drop, type-narrow, rename, NOT-NULL-on-existing) is split into **expand → backfill → contract** and is **forbidden as a single silent step** — it is gated by a declared `DataTruthScope` (below). Output lands in `back/gen/db/` (generated, never hand-edited) and is handed to **Atlas** as a *derived* migration; this step **emits and dry-runs** it, it does not commit it to a live truth DB.
  - `DataTruthScope` (KRD §44.3, verbatim) + a pure `RequireMigration(change) → (required bool, BlockReason?)` guard: a change whose `applies_to` touches `existing_records` or `historical_records` (i.e. a **historical-impact** change) **requires** a declared migration (`migration.required == true` with a `strategy ∈ {expand_contract, backfill, dual_read, dual_write}` and `audit.preserve_old_truth == true`); a change touching only `new_records` does not. A historical-impact change with **no declared migration** is **rejected** with a BlockReason (reuse S13's shape), never applied silently. `RequireMigration` is pure — no DB, no clock, no RNG; the change descriptor (the SemanticDiff `change_type` from S21 and the affected entity) is read from the argument, never fetched.
- **Atlas migration** (`back/migrations/`) — one declarative, **expand-only / append-only** migration adding the **`runtime.data_truth_scope`** record table: `id text PRIMARY KEY` (= `Hash(Canonicalize(body))`, content-addressed, S02 substrate), `body jsonb NOT NULL` holding the §44.3 shape (`applies_to[]`, `migration{required, strategy}`, `audit{preserve_old_truth}`), `entity_ref text NOT NULL` (the entity AST the data-scope governs), `migration_ref text NULL` (the emitted migration the declaration points at, in `back/gen/db/`), `version text NOT NULL` (= the hash), `superseded_by text NULL`, `created_at timestamptz NOT NULL`. Append-only (no `UPDATE`/`DELETE` of the body; head moves via a new row + `superseded_by`). **Testcontainers (Go)** with real Postgres applies both this migration and the emitted entity migration so the **dry-run** is verified against a real engine, not mocked. GRANTs: the agent DB role gets **SELECT only** on `runtime.data_truth_scope` and on `kernel.*` (it reads the entity AST + the data-scope, it never authors truth — the wall, §2); only the `aidos` CLI writer role inserts a `DataTruthScope` via an approved ChangeSet. The migration is expand-only/append-only and never alters or drops a prior table or GRANT.
- **Go package** `back/gen/db/` output (the emitter's **materialized migration**, NOT hand-written) — `EmitMigration` writes the expand-contract Atlas migration here with the protected header (`// CODE GENERATED BY AIDOS — DO NOT EDIT. source: <hash>`), per CLAUDE.md §4/§9: `back/gen/**` is generated, never hand-edited; this step *produces* it from the source.
- **BDD mirror** — the **db** projection's required mirror is a **fixture** (`state → command → events`: an entity change → `EmitMigration` / `RequireMigration` → the emitted migration + the require-verdict) plus a **`rapid` property** mirror for the ∀ invariants (determinism, expand-contract safety, "historical impact ⇒ migration required"), conceptually stored in the `mirrors` schema and materialized to `tests/` for the Go runner; the dry-run round-trip runs against **Testcontainers** Postgres. These **are** the done criteria (below).
- **Next route** `front/web/app/db-projection/` → `/db-projection` — the Workbench panel rendering the entity's **emitted expand-contract migration** (with its `source_hash` and a **dry-run valid / invalid** badge) and, for a change descriptor, the **DataTruthScope** (its `applies_to`, `strategy`, `preserve_old_truth`) plus the **REQUIRES MIGRATION / no migration needed** verdict (see "Visualisation UI").

> Explicitly **out of scope** (would be monsters / out of slot here): **no new MCP server** — emitting + dry-running a migration is the harness's inner codegen against an Atlas/Testcontainers engine; a callable `migrate`/`apply` backend op is a later persistence-runner step (if a real need emerges → record an **OpenQuestion**, do not build it now). **No new Hook** — the "no silent schema change over historical data" rule is enforced here as the **pure `RequireMigration` guard** the `aidos` writer's existing completeness/wall gate (S04/S12) will call, not a new non-bypassable Go binary; adding one now would be a dead hook (§5 hook-honesty). **No Skill** — emitting a migration from a source is inner codegen, not a new replayable human gesture (the `/project` skill from S34 already covers "emit a projection"; reuse it, do not fork). **No actual APPLICATION/commit of the migration to a live truth DB** — `EmitMigration` emits and **dry-runs** (Atlas validate / Testcontainers ephemeral apply) only; committing to the production truth store is the human-gated forward-only runner, a later tooth. **No backfill/dual-read/dual-write execution** — those `strategy` values are *declared* in DataTruthScope; their *runtime execution* is later. **No multi-entity / foreign-key migrations** — a single self-contained entity's db projection only (relations are a later step → OpenQuestion if a need appears). **No red-wave/impact re-implementation** — S22 owns the cascade; a `source_hash` mismatch or a missing required migration *feeds* it, it does not re-compute it. **No new SemanticDiff/ChangeSet machinery** — S20/S21 are consumed (the `change_type` drives `RequireMigration`), not re-built.

## Test minimal (done)

**Done = the emitted migration dry-runs valid, AND a historical-impact change requires a declared migration.** Restated **failing-first**, as the red BDD mirror to write **before** any code, conceptually stored in the `mirrors` schema and materialized for the runner. The **db** layer is a PROJECTION (KRD line 532), so the emitted migration is checked for faithfulness to its source and for expand-contract safety; the historical-impact rule is the §44.3 invariant. Done is **computed** (red set green ∧ prior green intact ∧ mutation score ≥ threshold ∧ no monster), never declared.

- **Workflow / fixture (N2 frozen slot: `state → command → events`, interpreted in Go; dry-run against Testcontainers Postgres)**, stored in `mirrors`, materialized to `tests/`:

  ```
  # mirrors schema · reflects: gen.db.{EmitMigration,RequireMigration} · test_kind: schema-validation/fixture · cert_language: fixture · authority: above

  fixture "the entity emits an expand-contract migration that dry-runs valid"     # THE done criterion (half 1)
    state   (entity head + prior):  Order @prior  →  Order @new (an additive column add, e.g. + coupon: string)
    command (emit):                 EmitMigration(Order@new, prior=Order@prior)
    events:  [ Emitted ]
    -> output is an Atlas migration carrying the protected header + the source_hash of Order@new
    command (dry-run):              atlas validate / apply on an ephemeral Testcontainers Postgres
    events:  [ DryRunValid ]
    -> the additive change is an EXPAND step (ADD COLUMN), no in-place rewrite/drop of existing rows
    -> re-emitting the same (Order@new, prior) gives byte-identical migration text

  fixture "a historical-impact change requires a declared migration"              # THE done criterion (half 2), §44.3
    state   (change):  a NARROWING change to Order (e.g. drop a column / NOT-NULL on existing) — applies_to includes existing/historical_records
    command (require): RequireMigration(change)            # no DataTruthScope declared
    events:  [ Blocked ]
    -> block_reason.code == "HISTORICAL_IMPACT_REQUIRES_MIGRATION"                # reuse S13 BlockReason shape
    -> no migration is emitted/applied silently (the old truth over historical records is preserved)

  fixture "a declared DataTruthScope unblocks the historical-impact change"       # the door, §44.3
    state   (change + scope):  the same narrowing change + DataTruthScope{ applies_to:[existing_records,historical_records],
                               migration:{required:true, strategy:expand_contract}, audit:{preserve_old_truth:true} }
    command (require):         RequireMigration(change)
    events:  [ Allowed ]
    -> the emitted migration is split expand→backfill→contract (forward-only), never a single destructive step

  fixture "a new-records-only change needs no historical migration"              # the rule binds historical impact only
    state   (change):  applies_to == [ new_records ] only
    command (require): RequireMigration(change)
    events:  [ Allowed ]                                                          # migration not required for new-only

  fixture "the DataTruthScope id is the content hash of its body"                # content-addressed (S02 reused)
    state   (scope):  DataTruthScope{ applies_to, migration, audit }
    command (compute): canonical-hash(body)
    events:  [ scope.id == Hash(Canonicalize(body)) ]

  fixture "an unknown migration strategy is rejected, not guessed"               # honesty: never invent a strategy
    state   (scope):  DataTruthScope{ migration:{ strategy:"teleport" } }         # not in the §44.3 closed set
    command (validate): RequireMigration(change)
    events:  [ Blocked ]
    -> block_reason.code == "UNKNOWN_MIGRATION_STRATEGY"                          # closed set: expand_contract|backfill|dual_read|dual_write
  ```

- **Invariant (∀) — `rapid` property test (Go), below the line, computational:**

  ```
  # reflects: gen.db.{EmitMigration,RequireMigration} · test_kind: property · cert_language: rapid · authority: below
  ∀ entity, ∀ prior:        EmitMigration is deterministic — same (entity, prior) ⇒ byte-identical migration text
  ∀ entity, ∀ prior:        EmitMigration is total over well-typed entities — never panics; an unknown shape ⇒ BlockReason
  ∀ additive change:        the emitted migration is expand-only (ADD), no in-place rewrite/drop of existing data
  ∀ narrowing change:       the migration is split expand→backfill→contract (forward-only), never a single destructive step
  ∀ change:                 applies_to ∩ {existing_records, historical_records} ≠ ∅ ∧ no declared migration ⇒ RequireMigration Blocks
  ∀ change:                 applies_to == {new_records} ⇒ RequireMigration Allows (no historical migration needed)
  ∀ DataTruthScope:         migration.strategy ∈ {expand_contract, backfill, dual_read, dual_write} else Blocked
  ∀ DataTruthScope:         a required migration ⇒ audit.preserve_old_truth == true (old truth never destroyed)
  ∀ scope:                  scope.id == Hash(Canonicalize(body)) — any byte change ⇒ a new version
  ```

Both start **red** (no `gen/db` emitter, no `EmitMigration`/`RequireMigration`, no `DataTruthScope` value object, no `runtime.data_truth_scope` table). That red **is** the `/goal` for this step. The fixtures are **means-tests toward the human red** (the emitted migration dry-runs valid ∧ a historical-impact change requires a declared migration) — **not** new truths the agent invents and then grades. The agent never invents a migration strategy, an `applies_to` value, or an entity field the §44.3 shape / the entity AST does not state.

## Regle anti-ecrasement

This step **edits only its own declared files** — `back/gen/db/**` (the emitter logic + the materialized migration it *produces*, never hand-authored), the new `back/migrations/<new>.sql` (the `runtime.data_truth_scope` table), the `mirrors`-stored fixture + `rapid` property materialized to `tests/`, `tests/e2e/db-projection.spec.ts`, and `front/web/app/db-projection/**` — and otherwise **adds new files**. It defines one new contract (the `EmitMigration` expand-contract shape, the `DataTruthScope` §44.3 value object, the `RequireMigration` rule, the `runtime.data_truth_scope` table) and changes none. Per CLAUDE.md §9: no rewrite of a prior artifact, no **hand-edit of generated files** (`back/gen/db/**` is emitted from the source — to change a migration, change the source/entity and re-emit, never edit the output), no silent model replacement, no touching prior Workbench routes; any prior `Stop`/wall hook is **composed/extended additively** (a new artifact may ADD a guardrail, never REMOVE one — §5 meta-loop rule). The migration is **expand-only / append-only** and never alters or drops a prior table or GRANT. Any change to a **prior contract** it depends on — S02's record substrate / `Canonicalize` / `Hash`, S04's wall GRANT set, S13's `BlockReason` shape, S21's `SemanticDiff` `change_type`, S34's emitter/ledger + `source_hash`, S35's `EmitDDL` / `Order` entity, the `kernel` schema shape — goes through a **ChangeSet** (`DRAFT → APPLIED`, completeness-gated) plus a **SemanticDiff** on the affected schema/mirror, never an in-place edit. An override is a recorded decision (ChangeSet + ADR + provenance), not an edit.

## Addendum (ADR 0006) — the Doltgres emitter target

This db-projection emits the datastore of the **app AIDOS builds** (the "BDD du résultat codé"), not the OS truth-store. Per **ADR 0006**, the emitter is **multi-target — but single-dialect (Postgres)**:

- **Postgres** target — the plain, non-versioned fallback (Testcontainers Postgres).
- **Doltgres** target — the **data-versioning** default: **Doltgres** is Dolt's Postgres-wire build, so the emitter renders the **same Postgres-dialect** schema + Atlas migration as for Postgres and points **the same sqlc/pgx/Atlas** at a Doltgres instance — **no MySQL, no second dialect**. Verified against **Doltgres in Testcontainers**, it gives the built app git-for-data (branch/merge/diff/`as of`). One source entity (S35) → one Postgres-dialect emission usable by both targets; `back/gen/db/` keeps the protected header + `source_hash` + expand-contract discipline unchanged.

Spike-gate: Doltgres is **beta** (no GA, ~5.2× slower, no pgvector, parser #2581 / locks #2600). Before building on the Doltgres target, **prove sqlc + pgx + Atlas introspection/diff against Doltgres in a Testcontainer** (the ADR 0004 low-confidence claims); if it fails, the emitted app falls back to the plain-Postgres target (the slot is `replaceable`).

Scope guard: the **OS truth-store stays Postgres** (the wall GRANTs, `runtime.data_truth_scope`, all of S01/S20/S24/S25/S26/S31 are Postgres — unchanged). The Doltgres target applies **only** to the emitted application's datastore. Open at execution: is Doltgres the default for emitted apps or opt-in alongside plain Postgres; and do emitted apps needing embeddings add a Postgres+pgvector sidecar (ADR 0006 open questions) — `/grill-with-docs` it before coding the target. Related: **S34** (register the Doltgres emitter) and **S46** (targets registry entry).
