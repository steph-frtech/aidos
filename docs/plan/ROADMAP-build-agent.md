# ROADMAP — Build-Agent : la couche gouvernée rendue opérante (`/long-run`-exécutable)

> *« en KRD un agent n'est jamais une autorité — c'est une couche gouvernée ; il propose, exécute, explore, mais ne déclare jamais seul ce qui est vrai. »* — l'en-tête gravé de `back/kernel/agentlayer/agentlayer.go`

## Intention

S52 a construit le **build-agent comme une couche gouvernée** : une `CoucheAgent` (la SOURCE, au-dessus de la ligne, content-addressed), le type d'événement `AgentRun` (télémétrie, sous la ligne), et **le mur** (`MayWrite`, `Validate`, `Propose`/`Approve`) qui tient cette couche. Tout cela est pur, total, sans horloge — **mais inerte** : rien hors des tests des paquets n'appelle ces fonctions. Le `CoucheAgent` est la *seule* SOURCE d'AIDOS sans projection (sans émetteur), `AgentRun.Agent` pointe vers un `@version` que rien n'instancie, `AgentAssignment` est une structure sans comportement, et la `RedWorkQueue` est un journal en écriture seule que nul ne lit pour dispatcher du travail.

Cette roadmap rend la couche **opérante** : elle construit le runtime **sous la ligne** qui consomme un `ContextPack`, réclame un `RedWorkItem`, et pilote une vraie session de codage LLM sur l'app de l'utilisateur — sous les contraintes déclarées. La discipline KRD est tenue à chaque pas : **mirror-first** (chaque pas nomme son miroir rouge BDD/property/fixture AVANT le code), **le mur** (l'agent ne déclare jamais une vérité : il propose via `idée → miroir → /goal → ChangeSet → approbation humaine`, jamais une écriture directe depuis le code ou l'écran), **determinism-first** (la coquille de la boucle, l'émetteur, le role-matching, l'arbitrage, la résolution de conflits sont du code déterministe ; le LLM est l'exception gatée, isolée à *une* fonction `GenerateAction` derrière une interface `ActionGenerator` avec un fake déterministe pour les tests — le code gagne, l'agent défère).

**Le principe d'ordonnancement (la colonne vertébrale) :** aucune capacité n'est exercée par un agent en marche tant qu'elle n'est pas (a) **DÉCLARÉE** dans la couche gouvernée et (b) **APPLIQUÉE** par un gate déterministe **fail-closed** (default-deny : ce qui n'est pas explicitement permis est refusé, jamais l'inverse). On ne **déclare** pas un axe pour ensuite l'**appliquer** ailleurs sans déclaration (interdiction d'enforcer une limite fantôme), ni l'inverse. La piste finit donc le MODÈLE (BA-E1 : l'émetteur `couche → implémentation` manquant, et les champs déclarés que la projection exige — `Temperature`, `MaxTurns`, `Seed`, confinement réseau/exec, `MaxConcurrency` — ajoutés à la SOURCE par `idée→miroir→/goal`), **scelle le périmètre d'application** (BA-E2 : un gate déterministe par axe déclaré — zone *deny-list* + chemin *allow-list fail-closed* + capacité + skill + coût + hook obligatoire + arbitre determinism-first, tous composés dans un verdict unique, prolongeant la forme de `MayWrite`), et **seulement ensuite** accorde l'autonomie (BA-E3 un agent confiné ; BA-E4 l'ordonnanceur avec leases *fenced* ; BA-E5 les équipes sans lost-update ; BA-E6 observabilité+coût+replay rédacté ; BA-E7 le retour-réalité). L'autonomie arrive en dernier, contre un périmètre déjà fermé.

> **Piste distincte.** Les identifiants sont `BA01…` (et non `Sxx`) : c'est la piste **BUILD-AGENT** (gouverner l'agent qui code l'app de l'utilisateur), distincte de la piste app-builder `Sxx`. Chaque pas reçoit son agent dédié `step-baNN` (§6 artifact-accretion) et ses pages Mintlify « Pour moi » (mandat, non énuméré ici). Insertion suggérée : un `BA_PLAN.md` séparé pour que `/long-run` dispatche la piste indépendamment.

## BA-E1 — Compléter le modèle couche→implémentation (l'émetteur manquant + les champs déclarés que la projection exige)

**Pourquoi.** Partout dans AIDOS une SOURCE émet une PROJECTION via un émetteur déterministe (S34–S38 : entity→Go/DDL/TS). Le `CoucheAgent` est la seule SOURCE sans émetteur. Avant qu'une boucle ne tourne, une `CoucheAgent` doit se projeter déterministiquement en `{modèle, system prompt assemblé, allowlist d'outils résolue, skills/hooks résolus, chemins autorisés/interdits, budgets, seed}`. Le prompt lui-même est une fonction pure des champs déclarés — determinism-first appliqué à la définition de l'agent. **Verrou clé (gap A) :** `AgentSpec` (vérifié, lignes 103–123) ne déclare AUJOURD'HUI ni `Temperature`, ni `MaxTurns`, ni `Seed`, ni concurrence, ni confinement réseau/exec — or deux runs « du même agent » ne doivent JAMAIS différer par un knob non gouverné. Ces champs sont donc ajoutés à la SOURCE **par la seule porte légale** (`idée→miroir→/goal`, car `AgentSpec` est au-dessus de la ligne) AVANT que l'émetteur ne les projette. Cet épic ferme le modèle pour donner aux pas d'application qui suivent une `AgentImplementation` unique, content-addressed, à appliquer.

## BA-E2 — Sceller le périmètre d'application (chaque axe déclaré devient un gate déterministe fail-closed)

**Pourquoi.** Une capacité déclarée mais non appliquée est du théâtre de gouvernance. Aujourd'hui le mur applique l'axe ZONE (`MayWrite`/`Classify`) mais les bindings, budgets et hooks sont du JSON inerte — `rg` confirme qu'aucun des serveurs MCP ne vérifie « cet agent a-t-il droit à cet outil ? ». **Distinction fondatrice (gap B1) :** le mur S04 est structurellement un *deny-list* (refuse les zones nommées, laisse passer le reste) — bon pour « les zones interdites sont d'accord » mais **insuffisant pour le confinement** d'un build-agent qui ne doit écrire QUE dans l'arbre de l'app de l'utilisateur. Le confinement est un *allow-list fail-closed* (default-deny). Ce sont deux invariants distincts ; cet épic construit les DEUX, plus un enforcer par axe déclaré — fonctions pures, totales, fail-closed — AVANT qu'une boucle ne puisse appeler un LLM. Chaque enforcer reprend la forme de `MayWrite` (entrée → verdict + `BlockReason`). À la fin, chaque axe qu'une `AgentImplementation` déclare (zone *deny* + chemin *allow* + capacité + skill + coût + hook + arbitre) a un gate qui refuse le non-déclaré, **et tous sont composés dans un seul verdict** que la boucle consulte. Aucune autonomie n'est câblée avant la fermeture de ce périmètre.

## BA-E3 — Accorder l'autonomie bornée : la boucle d'exécution sandboxée (un agent), avec re-check de CHAQUE action

**Pourquoi.** Seulement maintenant — modèle complet (E1), chaque capacité déclarée appliquée et composée (E2) — une vraie session LLM peut tourner, car chaque action est déjà gatée. Cet épic construit la COQUILLE déterministe autour de l'unique appel LLM irréductible : `claim → GateAction (avant) → re-check déterministe (après CHAQUE action) → record`. Elle utilise `evolve.Evolve` comme gabarit de boucle déterministe (replayable-by-seed), `goal.IsClosed` comme condition d'acceptation non-gameable, et TOUS les enforcers de E2 comme gate par tour. L'agent ne propose une vérité que via `idée→miroir→/goal→ChangeSet` (`Propose`/`Approve` de S52), jamais une écriture directe. À la fin, un agent gouverné pilote une vraie session red→green sur l'app de l'utilisateur sous contraintes prouvables, et **toute action (pas seulement celles qui changent du code)** porte un post-check déterministe.

|----|----------|-----------|
| **BA15** | Coquille de boucle `Drive(impl, item, pack, sensors, budget, now)` avec un générateur d'action MOCK — miroir fixture ROUGE d'abord : la coquille déterministe — réclamer l'item, par tour appeler `GateAction` (E2) AVANT que l'action ne s'exécute, sur vert exécuter l'action, sur tout verdict-faux enregistrer `AgentAction{Autorisee:false, RaisonBlocage}`, tick le `RunMeter`, boucler jusqu'à `goal.IsClosed` OU dépassement de budget OU `StopConditions` atteintes → émettre un `agentrun.AgentRun` complet via `Record`. ## Ce qui change vs S52 (gouvernance → exécution réelle)

S52 a construit le **modèle de gouvernance** : *data + le mur*. Tout y est pur, total, value-returning — et **inerte** (`grep` confirme que rien hors des tests des paquets n'appelle ces fonctions). Cette roadmap construit le **runtime sous la ligne** qui rend la couche opérante. Concrètement :

| # | Capacité | S52 (aujourd'hui) | Après cette piste | Épic |
|---|----------|-------------------|-------------------|------|
| 1 | Modèle + projection `AgentImplementation` | **absente** (le `CoucheAgent` est la seule SOURCE sans émetteur ; pas de temperature/seed/maxturns/concurrence/confinement déclarés) | SOURCE étendue par /goal + `agentimpl.Project(layer,cfg,pack)` — émetteur déterministe, couche→config runnable + prompt assemblé, cfg sans knob | BA-E1 |
| 2 | Application des axes déclarés | **JSON inerte** (aucun MCP ne lit les bindings ; le mur est deny-list seul) | enforcers purs `ToolAllowed`/`SkillAllowed`/`PathAllowed`(allow-list)/`Egress`/`Exec`/`HooksSatisfied`(vert)/`CheckBudget`(min)/`Arbitrate`(par structure) composés en un `GateAction` à précédence + règle arch « une seule fonction LLM » | BA-E2 |
| 3 | Boucle d'exécution sandboxée | **absente** (`agentrun` n'a que `Record`/`ApplyWall` post-hoc) | `agentloop.Drive(...)` — claim→gate→re-check de CHAQUE action→record ; LLM isolé derrière `ActionGenerator` ; confinement FS/réseau/exec réel ; identité MCP non-forgeable ; intégration transport prouvée | BA-E3 |
| 4 | Ordonnanceur `RedWorkQueue` | **différé** (queue en écriture seule ; le rôle agent ne peut transitionner) | `scheduler` + MCP sous un nouveau rôle avec `UPDATE` ; role-match, dep-honoring, lease/expire avec tick driver + fencing-epoch + anti-famine | BA-E4 |
| 5 | Équipes + orchestration | **taxonomie seule** (`Validate` traite les 3 kinds à l'identique) | `OrchestrationPolicy` immutable-par-run, `MaxConcurrency` déclarée+enforced, coordination de lease, hand-off, conflit same-file mergé (zéro lost-update) | BA-E5 |
| 6 | Ledger + coût + replay | **records only** (`economics.Evaluate` jamais nourri par un run ; `AgentRun` sans seed/impl/transcript) | schéma étendu (seed/impl/transcript, §9), compteur live + halt pré-call + stream-stop, `Replay` rédacté, effect-log réconcilié, UI ledger | BA-E6 |
| 7 | Retour-réalité | **moteur existe, pas d'on-ramp** (`rg agentrun reality` → rien) | `RunToSignal(run)` reliant runs échoués ET verts-creux à `reality.Observe→Learn→Idea`, identité-par-pattern, provenance vérifiée à l'apply | BA-E7 |

La ligne directrice : **`ApplyWall` cesse d'être un tampon post-hoc et devient un interceptor à verdict unique** ; les bindings cessent d'être de la documentation et deviennent des gates fail-closed sur chaque axe déclaré ; le confinement cesse d'être un deny-list et devient un allow-list ; la queue cesse d'être un journal et devient un dispatcher fenced ; un `AgentRun` cesse d'être une ligne append-only que nul n'apprend et devient un signal de réalité reproductible et auditable. **Ce que le mur garantissait en S52 reste vrai à chaque pas** : l'agent propose, exécute, explore — mais ne déclare jamais seul ce qui est vrai. La gouvernance n'est pas relâchée pour accorder l'exécution ; l'exécution est accordée *parce que* chaque action qu'un agent peut prendre est déjà déclarée, déjà gatée fail-closed, et déjà re-checkée déterministiquement.

## Récapitulatif `/long-run`

**7 épics, 31 pas (BA01–BA31).** Ordre de dépendance strict : **BA-E1** (modèle + champs déclarés, prérequis de tout) → **BA-E2** (périmètre scellé fail-closed sur chaque axe, avant tout appel LLM) → **BA-E3** (un agent autonome confiné contre le périmètre fermé, chaque action re-checkée) → **BA-E4** (l'ordonnanceur fenced qui le nourrit) → **BA-E5** (équipes en composition, concurrence déclarée, zéro lost-update) → **BA-E6** (garde-fous coût/replay-rédacté/audit) → **BA-E7** (la méta-boucle, échecs ET verts-creux). Chaque pas est mirror-first (miroir rouge nommé avant le code), respecte le mur (propose-not-approve ; déclare-avant-d'-appliquer ; allow-list de confinement distincte du deny-list de zone), est determinism-first (le LLM isolé à `GenerateAction` derrière `ActionGenerator`, prouvé par une règle arch-fitness ; chaque action arbitrée par structure et re-checkée), et livre sa surface `/agents` thémée+bilingue avec un Playwright e2e (ui-completeness, aucune capacité headless). Insertion suggérée : `BA_PLAN.md` séparé ; chaque pas reçoit son agent `step-baNN` et ses pages Mintlify « Pour moi » (mandat §6).
